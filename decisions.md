# Decision Log

## 2026-09-15 — Slide the analysis window with an in-place shift, not a circular index
**Choice:** The 1 s / 16,000-sample window is a flat FloatArray shifted left by
one 1,600-sample hop (System.arraycopy) each iteration, with the new hop
written at the tail.
**Why:** MicroFrontend.compute needs a contiguous chronological array, so a
true circular buffer would need a linearization copy of the same size anyway;
the shift keeps one buffer, zero per-loop allocations, and trivially correct
ordering at ~16k copies per 100 ms.
**Considered:** Circular buffer + copy-out (same cost, more index bookkeeping);
double-buffering (2x memory, no benefit).
**Prompted by:** Directive to move from non-overlapping 1 s inference to a
100 ms-hop sliding window.
**Touches:** app/src/main/java/com/example/final_test/MainActivity.kt

## 2026-09-15 — Pin MicroFrontend numerics with a synthetic-signal regression test
**Choice:** The parity test feeds a deterministic 120 Hz sawtooth +
fixed-seed Gaussian noise (java.util.Random(42)) and compares against a
checked-in 1960-float reference generated by the current implementation.
Singleton noise/PCAN state is reset via reflection before compute so the test
reproduces fresh-process output regardless of test ordering.
**Why:** No recorded clip exists in the repo; java.util.Random and
StrictMath make the signal bit-identical across platforms. The reference pins
current behavior (regression), not TF-op ground truth — documented in the
test.
**Considered:** Bundling a WAV clip (none available, adds binary weight);
mocking the singleton state by test ordering alone (fragile — JUnit order is
unspecified).
**Prompted by:** Directive Task 4; MicroFrontend's stateful estimators made
naive testing order-dependent.
**Touches:** app/src/test/java/com/example/final_test/, app/build.gradle.kts
(unitTests.isReturnDefaultValues for the android.util.Log call in compute)

## 2026-09-15 — Ship the INT8 model in assets/, loaded via Interpreter
**Choice:** conv_int8_model.tflite lives in app/src/main/assets/ and, when
USE_INT8_MODEL = true, is run through org.tensorflow.lite.Interpreter with
explicit input/output quantization (scale/zero-point from the tensors,
handling both UINT8 and INT8).
**Why:** Dropping it in app/src/main/ml/ would trigger mlModelBinding codegen,
and the generated TensorBuffer API hides quantization params — the Interpreter
API exposes Tensor.quantizationParams(), which the directive requires handling
correctly.
**Considered:** ml/ folder + generated binding (no access to quant params;
codegen for a metadata-less quantized model is fragile).
**Prompted by:** Directive Task 5.
**Touches:** app/src/main/assets/conv_int8_model.tflite, MainActivity.kt
